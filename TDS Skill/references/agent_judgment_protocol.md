# TDS Agent 判断协议

本文件是 TDS Skill 的判断层，不是另一套模板或另一套业务规则。它约束 Agent 如何使用强标注框架、源文证据和程序结果；具体术语、归类和译法仍必须根据当前源文件判断。

## 1. 先分层，再覆写

每个事实至少分成三层：

1. `source evidence`：从原始文档逐字抽取的文本、表格单元格、段落位置、语言和源文件 hash。不可用模板内容补齐，也不可丢弃限定条件。
2. `normalized semantic model`：对源事实进行整理、归纳、统一命名、单位/符号规范和结构化后的模型。每个值必须能回溯到一个或多个 source evidence，并保留判断理由。
3. `presentation value`：在具体 CN/EN、冠志/国彩模板槽位中展示的值。它只能来自标准化模型；模板只贡献结构、固定标签和格式。

不要直接从源文档写四个模板，也不要先写中文模板再把已排版的中文逐段翻成英文。英文输出使用标准化模型中的事实、限定条件和结构，再由 Agent 选择专业、自然且不改变含义的英文表达。

## 2. 什么是硬约束，什么需要判断

硬约束包括：

- 用户强标注的检索范围、章节/字段框架、模板结构、序号列和标签列格式、mutation whitelist、源事实隔离、四变体身份、八文件矩阵和 PDF 派生路径。
- 源文件明确给出的产品名称、性能值、单位、条件、测试方法、产品特性和公司事实。
- 一旦会改变客户含义，任何未经来源支持的新增分类、结论、危害、毒理、生态、性能声明或合规判断都不能自动加入。

需要 Agent 判断的包括：

- 一个源段落的起止边界、标题与正文的归属、表头与数据行的识别。
- 同义词归类、一个概念拆成多个字段或多个句子合并成一个字段；判断必须同时考虑上下文和限定条件。
- 单位/符号的标准写法、数值范围表达、测试条件保留、列表顺序和是否应在目标模板中显示。
- 专业英文术语、句法、复数/冠词、大小写、标点、标签短语和段落重组。
- 源文有数据但字段名称与模板不同的映射；模板没有同语义槽位时，优先保留为源顺序扩展项，不为了“填满模板”强行归类。

别名表是候选提示，不是自动批准；模板示例是结构参考，不是产品事实；历史产品、其他语言或其他公司的输出不能作为当前产品事实。

## 3. 每次判断留下什么

标准化模型至少应留下：

```json
{
  "field_id": "performance.row.004",
  "source_values": {"zh-CN": "7.0-9.0"},
  "normalized_values": {"zh-CN": "7.0-9.0", "en-US": "7.0-9.0"},
  "provenance": {"zh-CN": ["table[0].row[4]"], "en-US": []},
  "decision": "preserve_as_source_row",
  "reason": "源标签含有与模板固定字段不同的限定条件，保留原行而不强行归类",
  "confidence": "high",
  "needs_judgment": false
}
```

`source_values` 是证据，`normalized_values` 是允许覆写的值。对英文，`normalized_values.en-US` 必须是 Agent 根据标准化语义模型做出的专业翻译；如果只有英文源文件，它可以作为翻译参考，但仍应说明其与标准化模型的关系。若判断尚未完成，设置 `needs_judgment: true`，构建只能输出诊断结果并保持 `RELEASE_FAIL`。

程序生成的模型默认是 `status: candidate`。Agent 完成逐项判断、补齐英文专业译文并确认没有未决含义后，才可将模型提升为 `status: approved`；不能通过只改状态而不补证据来绕过判断门。

## 4. 翻译判断门

英文翻译必须：

- 保留事实、范围、数量、单位、温度、时间、比例、测试方法、否定词和限定条件；不得把“约”“≤”“无数据”“不适用”等弱化、强化或改成另一结论。
- 允许为英文自然表达而调整语序、词形、标点、句子边界或固定术语，但每个变化都要能回溯到同一标准化事实。
- 不得凭行业常识补充性能、法规、危险性、毒理、生态、用途、认证或结论；专业语言不等于擅自扩写。
- 标签、表头、序号和模板固定文案按目标语言模板处理；产品值、性能值和特性值从标准化模型处理。标签列的格式仍受白名单保护。

如果直译会产生歧义，先回到源文上下文和标准化模型判断，不用固定翻译表掩盖不确定性。不能确认时保留原始证据、标记判断项并阻断发布。

## 5. 覆写与审计顺序

1. 先审阅抽取结果和 decision ledger，再允许标准化模型进入覆写。
2. 以对应语言/公司的 active 模板 fresh clone，按 whitelist 原位写入 presentation value。
3. 性能行保持源顺序、原始标签和限定条件；模板示例行没有源事实就裁剪。新增行只克隆模板样式。
4. 对四个 DOCX 做内容、事实、几何、保护部件和语言/公司 parity 审计。
5. 只从审计后的最终 DOCX 转 PDF，再做同名配对和八文件审计。

自动审计通过只表示可交给用户校对；它不替代 Agent 对语义、译文和页面视觉效果的判断。

## 6. 不要被固定思维带偏

每次任务重新读取当前源文档、当前模板基线和当前用户标注。不要因为“以前这个标签通常属于某字段”“模板以前有这个示例行”“英文以前这样写过”就跳过上下文判断。能证明的事实才进入模型，不能证明的内容要么保留为证据，要么明确标记并阻断。

## 7. 无源章节整节隐藏

源文件没有对应说明的标题，不写“无数据”，整节隐藏（标题段+内容段删除）：

1. 只有程序给出的 `hide_no_source_candidate` 且 Agent 核对源全文确认无对应内容时，才可将该字段提升为 `hide_no_source`（`needs_judgment: false`，两语言 `normalized_values` 保持为空）。
2. `product.title` 永不隐藏；标题缺失直接阻断发布。
3. 隐藏是删除，不是清空占位；审计按删除后的几何校验，未隐藏的章节不受影响。
