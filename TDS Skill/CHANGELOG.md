# Changelog

## 1.3.19 — 2026-09-15

- 恢复英文叙述正文的模板首字双空（`firstLineChars=200`、`firstLine=480`），产品特性保持编号列表的悬挂缩进，避免把两种段落格式混用。
- 增加源数据驱动的 2-col / 3-col / 4-col 性能表拓扑收敛：只裁剪未使用列并沿用有效单元格格式，2 列模式释放空列占用的横向空间。
- 放宽审计为 registry 授权拓扑白名单，同时增加 PDF 单页契约检查和 `pypdf`/`pdfinfo` 双路径页数读取；同步修复旧字段回退导致的 2 列误判。

## 1.3.18 — 2026-09-14

- 按用户提供的新中英文冠志/国彩版式刷新四个 active DOCX 模板；保留模板版式与表格框架，不把 PU-1001 业务文本作为运行时模板数据。
- 将产品特性与应用分别收敛为单一可扩展模板槽，额外内容仅通过 registry 授权的模板段落克隆写入，修复重复应用段和无匹配节空行占位。
- 清理英文模板正文、标题、表格的残留字体继承与 `firstLineChars` 首行缩进，统一英文内容的 Times New Roman 西文字体属性；同步更新注册表、结构快照与回归测试。

## 1.3.17 — 2026-09-14

- 用用户提供的英文冠志/国彩 `.doc` 模板替换 active DOCX 与 source DOC；英文正文、产品特性、应用、储存和性能表格现在直接继承新模板的字体与 Run 结构。
- 同步英文模板注册表、SHA-256 基线和段落槽位；支持新模板的独立英文标题与四条产品特性占位段。
- 保持模板原有的空单元格结构：空目标值不会凭空创建 Run；模板继承回归测试恢复全绿。

## 1.3.16 — 2026-09-14

- 固化“模板唯一权威、只替换文本”的覆写规则：段落与表格写入保留模板原有 Run、`pPr`、`rPr`、字体、字号、缩进、间距、编号和制表位，不再使用 `p.text` 重建段落或强制注入字体格式。
- 多 Run 模板选择原始最长文本 Run 作为文本锚点，只替换文字并保留其他 Run 节点；标题、正文、产品特性和表格单元格统一走同一模板继承路径。
- 审计恢复对编号段落 Run 级格式的严格比对，并新增产品特性 Run 形状回归测试。

## 1.3.15 — 2026-09-09

- 统一修复产品特性缩进对齐与制表位：四款中英文模板（冠志/国彩）产品特性段落统一重设悬挂缩进 `left=840 twips`, `hanging=360 twips`，使特性序号 `1.` 起始位置严格位于 480 twips（精准对齐正文 `firstLineChars=200` 首字），并将首制表位设为 840 twips，彻底消除序号与正文之间的过大空隙。
- 完善产品特性多条同格式动态拓展：支持 3 条及以上特性条目按模板段落深拷贝克隆写入（不再限制 2 条），严格继承模板字体、字号与段落属性。
- 增加文末空白自适应收束（tail_blank_trim）：在多条特性拓展导致尾部纯空白占位段溢出为第 2 页时，按 registry 授权安全收束文末多余空段，确保全套中英文四变体交付物 100% 维持单页严格标准。
- 同步更新注册表与基线快照：更新 `template_field_registry.json` 与 `template_baselines.json` 中的段落几何度量，全套 23 项自动化测试均通过验证。
- 增加严格模板门禁：禁止自动修改标题定位、段落/字符格式、缩进、间距、编号、制表位和空白分隔段。
- 修正“包装储存”源章节边界，避免储存内容被误并入产品特性。

## 1.3.13 — 2026-09-08

- 标题遵循模板：保留模板字形与间距，只去除示例定位缩进并居中；长产品名不再被示例缩进挤向右侧。
- 无匹配章节整节隐藏时连带删除其相邻空白分隔段，不再残留叠空行占地；隐藏规则由覆写与审计共用同一模板权威函数。
- 应用、储存等多行值按行拆分到模板段落克隆中逐段写入，禁止段内非法换行；空行永不落地。
- 版式以模板克隆为唯一权威：新增标题居中、禁段内换行、隐藏节空行三项审计，覆写与审计的隐藏/扩展模型保持一致。

## 1.3.12 — 2026-09-07

- 基于官方 1.3.11 的本地增量：特性合约审计支持应用章节隐藏（右界回退链应用→储存→文末），隐藏章节缺失时不再崩溃。
- 构建收尾自动打印交付清单（输出根目录 + `WORD/`/`PDF/` 路径字节数 + release report 状态）；审计清单加“交付报告”必检项。

## 1.3.11 — 2026-09-07

- 将 TDS PDF 发布链路切换为内置 WPS/Word-compatible `word2pdf` 转换器：先生成并 preflight 最终 Word，再逐个 Word 派生 PDF；禁止 LibreOffice fallback、独立 PDF 制作和 PDF 后编辑。
- 增加 PDF 转换证据、来源/目标哈希校验、转换器版本和页数记录，最终审计阻断非最终 DOCX 来源或缺失转换证据的 PDF。

## 1.3.10 — 2026-09-07

- 新增已验收的应用正文多行布局与序号清理参考实践，记录 OOXML 定位、呈现层最小修复、四变体验证和产品产出与仓库隔离要求。

## 1.3.9 — 2026-09-07

- 将产品产出物与技能仓库隔离写入规范：Word、PDF、审计资料、mapping、generation record、执行日志和产品级中间文件不得加入、提交或推送到 Git；`output-dir` 必须位于仓库外。
- 修复应用正文的多行布局：清理源文本残留序号，统一换行后的正文起点，避免中文应用从 `2.` 起号以及续行回到段落左边界。

## 1.3.8 — 2026-09-07

- 分离产出目录：Word 文件统一写入 `WORD`，PDF 文件统一写入 `PDF`，生成元数据和覆写执行日志归档到 `audit/generation` 与 `audit/execution_logs`。
- PDF 转换和八格式审计支持分离目录，同时保留旧的脚本直接调用兼容性。

## 1.3.7 — 2026-09-07

- 英文 TDS 输出统一使用专业章节标题，优化 `waterborne polyurethane dispersion`、产品特性、应用、储存及性能指标术语和句式；统一 `forced-air oven`、`MPa`、`mPa·s`、范围符号等技术写法。
- 英文源文档提取兼容 `Product Description`、`Product Features` 等标准化标题。
- 每次 DOCX 覆写生成独立的 `.overwrite.log.json` 执行日志，并在 generation record 中回链，记录模板、字段写入、产品特性布局、性能行写入、章节收尾和失败信息。

## 1.3.5 — 2026-09-07

## 1.3.0 — 2026-09-04

- 明确 TDS 主链路为“原始证据抽取 → 事实整理/语义标准化 → 专业英文翻译 → 模板原位覆写”，不再把源值和最终覆写值视为同一层。
- 为标准化模型增加 `source_values`、`normalized_values`、provenance 和 decision ledger；性能行保留原始值与标准化输出值两套证据。
- 增加 Agent 判断协议：强标注框架和白名单是硬约束，别名、模板示例和历史案例只是线索；歧义未解决时 fail closed。
- 英文覆写明确以标准化模型为唯一输出来源；英文源文件只作为目标语言证据/校验材料。
- CLI 增加 `--normalized-mapping`，支持 Agent 审批后复用同一标准化 mapping 构建，避免重复抽取和重复排版。

## 1.2.0 — 2026-09-04

- 将性能表覆写改为源文件主导：严格保留源行顺序、项目名称、限定条件、指标值、单位和测试方法；裁剪未使用的模板示例数据行，超出容量时才克隆行。
- 禁止不同检测条件的语义归类，新增源文件—输出文件逐行 parity 审计和明确的发布阻断。
- 将真实 PU-1001/PU-1002 回放纳入验证，避免仅验证模板外观而遗漏源事实错误。

- 建立四 DOCX + 四 DOCX-derived PDF 的八格式构建和发布审计入口。
