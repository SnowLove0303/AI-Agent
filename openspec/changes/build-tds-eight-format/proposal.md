# Proposal: Build and harden independent TDS eight-format standardizer

## Goal

把现有四份用户维护的 TDS 模板内化为独立的 `TDS Skill`，建立一次抽取、一次语义归一、四变体逐一映射、四份 DOCX 及其派生 PDF 的可审计流水线。

本次优化修复真实 PU-1001 回放暴露的根本问题：性能表不能由模板示例字段驱动覆盖源事实。性能表以源文件为事实主线，严格保留源行顺序、原始项目标签、限定条件、指标值、单位和测试方法；模板只提供表格几何、样式和受控扩展能力。

## Scope

- 覆盖 TDS：中文/英文 × 冠志/国彩四个模板变体。
- 交付矩阵：四个最终 DOCX + 四个由对应最终 DOCX 转换得到的 PDF。
- 每个变体保留自己的模板几何、语言和公司骨架；映射共享同一 TDS semantic model。
- 模板示例产品、数值、成分、性能和公司事实只用于建立结构基线，禁止写入其他产品。
- TDS 源码、模板、映射、审计和测试放入独立 `TDS Skill`，不改写或导入 `MSDS Skill` 的业务实现。
- 增加源文件—输出文件逐项 parity 审计，阻断源行丢失、重排、标签/限定条件改变、虚构模板指标和语言事实缺失。

## Non-goals

- 不重建表格，不把四个变体合并成一个物理模板。
- 不根据模板示例事实补全源文件缺失的数据。
- 不为 PDF 单独排版或维护独立 PDF 内容。

## Acceptance

1. 四份模板均有来源哈希、DOCX 基线和结构 snapshot/hash。
2. 一份来源数据可以经统一语义模型生成四个模板对应的 DOCX；性能表输出逐行保留源顺序和源标签，无法保持语义时明确 fail-closed。
3. 模板缺失的源性能指标只作为受控扩展行追加；模板存在但源文件不存在的示例指标不得新增为“无数据”行或冒充产品事实。
4. 四个 PDF 均由最终 DOCX 转换得到，八文件矩阵、模板几何、源事实 parity、语言 parity、白名单和事实隔离审计通过。
5. 自动测试、OpenSpec 校验、V2.9/MSDS 继承审计和 TDS 专项审计结果被保留；任一发布阻断失败不得标记通过。
