## Context

现有 MSDS Skill 已有模板快照、geometry、白名单、Section 特例、四格式、八文件、PDF 转换和 V2.9 inheritance 检查，但这些检查分散在多个脚本与文档中，缺少一个统一的交付判定和证据模型。设计必须围绕 V3.9 的既有入口与输出契约增加审计层，不改变模板或产品事实处理。

## Goals / Non-Goals

**Goals:**

- 将所有现有 release blocker 统一登记为带规则编号的清单。
- 以固定权重计算 100 分质量分，并让 B0/B1 优先于分数。
- 为每个检查输出稳定、可追溯的 JSON evidence record 和人类可读报告。
- 在一个 orchestrator 中串联现有审计器、DOCX/PDF 配对和逐页 QA。
- 为真实 PU-2345 与 OS-9015 八文件输出提供可重复回放入口。

**Non-Goals:**

- 不替换 CN/EN 维护模板，不修改 geometry snapshot/hash。
- 不重新设计 DOCX 表格、不改变受控序号列或标签列格式。
- 不把模板示例事实、外部推断或新的法规判断引入 semantic model。
- 不新增外部服务、数据库、运行端口或强制依赖。
- 不删除或覆盖 V3.8、V3.9 及其他历史版本包。

## Decisions

### 1. Use a versioned checklist registry as the single audit source

清单登记表将成为规则的唯一索引，包含 rule id、类别、权重、严重性、输入、通过条件和 evidence kind；文档由同一登记表解释。选择登记表而不是继续依赖脚本文件名，是为了避免“文档写了但没运行”或“脚本运行但没有客户可理解标准”的漂移。替代方案是只扩充 `SKILL.md`，但它无法稳定提供程序化覆盖率和每条规则的证据。

### 2. Keep existing audits as adapters behind one orchestrator

新增评判层负责输入发现、规则编排、评分、阻断优先级、报告和覆盖率；已有 geometry、whitelist、Section、四格式、PDF 和 inheritance 审计继续作为受控检查适配进入统一结果。这样可以保留已验证的 V3.9 行为，降低重写模板相关逻辑造成格式回归的风险。替代方案是重写成单一大脚本，短期代码较少但会复制规则并增加维护风险。

### 3. Treat evidence completeness as a release gate

每条必需规则必须有一条结果，即使执行错误或输入缺失也必须显式记录。`NOT_CHECKED`、`ERROR` 和缺证据不能被当成通过。这样审计报告可复核、可追责，并避免用户看到一个看似通过但实际有项目未检查的总分。代价是早期会暴露现有脚本没有结构化输出的缺口；通过适配器将旧脚本输出封装为统一记录解决。

### 4. Separate score from release outcome

权重分只用于质量分层和扣分解释，固定为源事实与语义 30、模板结构与受控覆写 25、DOCX 版式与视觉质量 20、四格式语义/公司一致性 10、DOCX 到 PDF 派生与 PDF 质量 10、发布包与审计证据完整性 5；B0/B1 是不可覆盖的 release blocker；B2 可以在阈值达标时保留为观察项。选择分数与 outcome 分离，是为了防止高分掩盖模板骨架、源事实泄漏或 PDF 不可追溯等客户风险。替代方案是单一通过率，但它无法表达质量差异，也无法确保高风险项优先。

### 5. Use deterministic package discovery and pair validation

审计器根据固定的产品、语言和公司矩阵解析文件，逐一验证 DOCX/PDF 配对，并在歧义时失败。不会从任意临时文件中“挑一个看起来最像的版本”。这样与八文件交付契约一致，也能减少多版本目录导致的误审。输入目录可通过参数指定，但不会创建第二套正式产物目录。

## Risks / Trade-offs

- [旧审计器输出格式不统一] → 通过适配器把退出码、JSON/文本和异常转换为统一 evidence record，并将转换失败标记为 ERROR。
- [评分权重被误解为法规合规结论] → 报告明确质量分是内部交付门，不替代法规责任人的最终审阅；B0/B1 仍按规则强制阻断。
- [逐页视觉 QA 难以完全自动化] → 自动检查页面尺寸、页数、文本/图片存在性和异常；关键页保留渲染图证据，并在清单中要求逐页状态，不以“脚本成功”替代视觉证据。
- [EN 模板窄列导致合法换行与真正截断混淆] → 保留模板 geometry 基线，使用文本溢出/页边界/关键页人工复核组合判断，不通过重建表格解决。
- [真实输出不在 GitHub Skill 文件夹内] → 测试提供受控 fixture/路径参数；发布包只包含可复现的规则、脚本和测试，不复制用户产品数据作为模板事实。
- [清单与代码发生漂移] → 增加规则覆盖审计，要求清单 rule id、实现注册和测试映射数量一致，缺项直接阻断发布。

## Migration Plan

1. 在 V3.9 基线之上新增审计标准、清单、阻断目录和证据 schema 文档。
2. 实现规则注册表、评分器、证据记录器和统一 orchestrator；接入现有审计脚本。
3. 使用 PU-2345 和 OS-9015 的现有八文件输出回放，修正只涉及审计层的兼容问题。
4. 增加边界、覆盖率、证据完整性和 ZIP 完整性测试，运行既有全部测试。
5. 将同一套变更同步到本地 V3.9 包的目标新版目录，重新构建 V3.4 交付 ZIP；保留历史包。
6. 若新审计层失败，回滚新增审计文件和版本标识，V3.9 既有生成与审计入口保持不变。

## Open Questions

无。评分阈值、阻断优先级、输入矩阵和证据字段均属于本次验收契约，不能延后决定。
