# MSDS 发布阻断目录 v1.0

## B0 — 立即阻断

B0 表示交付包的身份、模板骨架或发布可信度已经失效：

- 八文件矩阵缺失、重复、零字节或无法唯一配对（ID-001）。
- 输出不能证明来自当前维护模板，或 geometry/hash 不匹配（TPL-001）。
- 序号列、标签列、合并关系、宽度、边框、受保护 XML 或格式被越权修改（TPL-002/TPL-003）。
- PDF 不是对应最终 DOCX 的派生物（PDF-001）。

B0 必须修复后从头重跑完整审计；不能以人工检查、备注或分数豁免。

## B1 — 客户交付前必须修复

B1 表示客户会看到错误、事实不可靠或跨格式不一致：

- 源事实缺失、错误归类、示例事实泄漏或不受支持的推断。
- Section 2/3/8/9/11/14 不符合已确认的内容和排版契约。
- 四格式事实、章节 presence 或公司信息不一致。
- DOCX/PDF 存在截断、缺图、空白页、溢出、页数异常或关键页不可读。
- V2.9 inheritance、release audit 或 manifest/ZIP 检查失败。

B1 必须在客户交付前关闭，并重新生成受影响的 DOCX 和 PDF；不得只改 PDF。

## B2 — 记录并治理

B2 表示不直接破坏强制发布契约，但影响可读性、维护性或后续复核，例如轻微可读性问题或报告说明不足。B2 必须进入报告和整改记录；当无 B0/B1 且达到评分阈值时，可以保留为观察项。

## 处理优先级

`B0 > B1 > B2`。任何 B0/B1 存在时 outcome 必须是 `RELEASE_FAIL`。没有硬阻断但有未检查/错误证据时是 `NOT_READY`。只有所有必需规则完成且分数 ≥95 才能 `RELEASE_PASS`。
