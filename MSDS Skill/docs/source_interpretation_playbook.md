# MSDS 源文件解读、取舍与覆写说明书

本说明书是 Agent 在处理源 MSDS/SDS 前必须遵守的操作手册。它解决的
不是 Word 排版，而是“有没有完整读到源文件、有没有把事实放到正确字段、
有没有在取舍时丢失信息”的问题。

## 总原则

源文件是事实权威，正式模板是表格、格式和标签权威。Agent 不得把自己的
语义理解直接写进模板；必须先形成可审核的事实证据，再形成源字段到模板
字段的映射，最后才允许通过受控边界覆写值字段。

没有证据的值不能写入；没有处理结论的源事实不能算作已完成；有歧义、冲突
或未读区域时必须阻断，而不是猜一个最像的字段继续生成。

## 标准工作流

### 1. 读取前：锁定输入和规范

- 读取完整 `SKILL.md`、`openspec/agent_overwrite_contract.md` 和
  `openspec/source_interpretation_contract.md`。
- 记录源文件原始路径、格式、SHA-256、模型和修订信息。
- 只选定一个原始源文件。已生成的 MSDS、旧输出、渲染 PDF 和临时目录不能
  作为新源文件。
- 读取模板的版本和哈希，但不要把模板中的示例值当作产品事实。

### 2. 源文件体检：先确认“读全了”

建立 `source_coverage`，至少记录：

- 非空段落/表格单元格/逻辑行的稳定 `unit_id`；
- 表格数量、处理数量、图片数量和图片核对数量；
- 跨页表格、合并单元格、嵌入对象和扫描区域；
- 所有表格单元格内的嵌套表格；尤其是 8.2 的四列控制参数表，必须逐表、
  逐表头、逐数据行登记，不能只读取外层单元格的 `cell.text`；
- `unmapped` 和 `unreadable` 清单；
- 源文件 SHA-256。

只有以下条件全部满足，`source_coverage.status` 才能是 `ready`：

- 所有已发现的源单元都已提取或明确标记为结构性内容；
- `unmapped` 为空；
- `unreadable` 为空；
- 所有检测到的图片、扫描页和跨页表格都有处理记录；
- 计数和实际 `source_units` 数量一致；
- `nested_table_count` 和 `nested_source_unit_count` 与嵌套单元清单一致；
- 每个证据记录使用同一个原始源文件哈希。

`source_absent` 只表示“已经读过，源文件没有这个字段”。它不等于：

- `source_unreadable`：发现了内容但无法可靠读取；
- `mapping_ambiguous`：读到了内容但不能唯一归类；
- `mapping_conflict`：不同源位置给出了相互冲突的内容；
- `unmapped`：提取器发现了但还没有放入事实模型的源单元。

后三类不能被转换为空值行来绕过检查。

### 3. 事实提取：只记录源事实，不急着归类

每一条事实进入 `fact_ledger`，并包含：

```json
{
  "fact_id": "FACT-0001",
  "source_section": "s9",
  "source_locator": "s9.table[9].row[4].cell[2]",
  "source_text": "闪点：> 100 °C",
  "normalized_value": "闪点：> 100 °C",
  "source_unit_ids": ["SRC-T09-R005-C02-L01"],
  "evidence_type": "explicit",
  "mapping_status": "pending",
  "line_break_policy": "verbatim_single_line"
}
```

提取时必须保留：

- 原始数值、单位、范围、上下限、约等于符号和负面结论；
- CAS/EC 号码和代码的原始写法；
- 有意义的逻辑换行；
- 研究方法、物种、暴露途径、证据限定词；
- “不适用”“无数据”“未满足分类标准”等明确结论。

不要在这个阶段凭常识补全，也不要因为某个词看起来像模板标签就直接写
模板。翻译不产生新事实，任何派生值必须记录来源事实和批准的转换规则。

### 4. 字段归类：按语义注册表，不按位置猜

每条事实必须经过 `source_mapping` 审核。映射必须说明：

- 源章节和源位置；
- 目标章节；
- 目标语义字段/槽位；
- 归类依据；
- 值的换行策略；
- 该事实是保留、隐藏、合并还是不适用。

表格行位置、相邻标签或“看起来最接近”都不是足够依据。章节相似但含义
不同的内容必须分开处理，例如理化性质、毒理学、运输信息和法规信息不能
因为都出现“危险/分类/数据”而相互挪用。

Section 8.2 的源文件如果把控制参数放在外层表格的嵌套表格中，必须先
还原为完整的 `物质 / 依据 / 类型 / 数值` 记录，再映射到模板已有的四列
数据行。没有成功还原的嵌套记录必须进入 `unreadable` 或 `unmapped`，不能
直接把工程控制块判定为空。

Section 2.8 的吸入、食入、皮肤、眼睛及症状/体征必须按源文件明确标签
分别建账。整体 GHS 结论（例如“未被分类”）不是任何一个暴露途径的值；
不能因模板有重复的 2.8 行就按位置复制。没有源值的途径先保持空值，随后
隐藏完整行并重新整理显示编号，后续途径的值不得前移到错误标签。

Section 2.5 的 H/EUH 语句与健康危害行必须按暴露途径逐项比对：H 语句覆盖
皮肤时只抑制皮肤行，不能连带抑制吸入、食入、眼睛或症状/体征；未被 H 语句
覆盖的途径必须回查源文件 2.7/2.8 并保留全部源值。2.6 事故响应中的
“吸入：/食入：/皮肤：/眼睛：”是急救说明，留在防范说明原文组内，不得当作
健康危害值。任何去重都不得改写、合并或虚构源文本。

Section 8 的防护记录必须先恢复标签和值的边界，再做模板映射。标签单元格
中的制表符、同行内值和有意义换行只用于识别边界；如果同时存在独立值单元格，
以独立值单元格为准，并把污染尾巴列入复核。呼吸、手部、手套材料、FKM、IIR、
NBR、建议、眼睛和身体防护是独立记录；不认识的标签必须进入 `unmapped` 或
`unreadable`，不得按源行序号硬塞进模板。

Section 9 中的 `NCO含量` / `NCO content` 是独立理化属性。若它与
`其他信息`写在同一源单元格内，先拆成独立事实，再决定是否使用已有或
允许新增的属性行；不得因为它出现在其他信息旁边就把它当作普通备注吞掉。

对于成分，至少同时核对名称、CAS 和含量；对于研究结果，至少核对终点、
途径、物种、结果和方法；对于运输信息，必须分开核对 UN 编号、运输名称、
危险类别、包装类别和特殊防范措施。

### 5. 灵活取舍：保留事实，选择正确表示

#### Section 2 专用事实路由

Section 2 必须先建立稳定语义路由，再决定显示编号。`emergency_overview`
只能接收源文件明确写出的 Section 2 应急概述事实，不能把危险性说明、物理
和化学危险、健康危害或其他危害概括成 2.1。`ghs_classes`、`label_elements`、
`signal_word`、`hazard_statements`、`precautionary_statements`、
`physical_chemical_hazards`、`health_hazards`、`environmental_hazards` 和
`other_hazards` 默认各自拥有事实，不允许一条事实跨目标重复。只有在
`section2_routing` 中明确记录 `shared`、完整目标清单和理由时才可例外。
路由必须同时与 `source_mapping`、`output_traceability` 及 CN/EN 语义值一致；
`s2.row[1]` 这类只按位置命名的目标不能用于正式覆写。

S2 防范说明还必须保留源文件的分组边界。`预防措施：`、`事故响应：`、
`安全储存：`、`废弃处置：`（以及对应英文标题）是源事实的语义小标题，
不是模板标签。先按源顺序抽取为分组事实，再统一投影到模板现有的防范说明
值单元格；每个有 P 语句的分组标题独占逻辑行，后接该组的 P 语句。没有
P 语句的孤立标题不显示。标题与 P 语句同行时，必须在确认的边界处分开，
不得把标题粘到前一个语句末尾。源中存在的有效分组不得扁平化、归入其他、
标记为 duplicate 或静默丢失；CN/EN 输出追溯必须能分别找到对应标题。

“灵活”只发生在内容如何适配固定模板，不代表可以改标签或随意删信息。

允许的取舍：

- 多个同一目标字段的事实，在注册字段允许时合并到同一个值单元格；
- 使用语义换行把一个值整理成清晰的字段行；
- 对超出模板容量且规则允许的成分、理化性质、控制参数或法规项目增加完整
  的样式行；
- 对没有源依据的模板示例行进行隐藏；
- 对真正的源文件缺失值执行隐藏或清空，并在台账里记录原因。

不允许的取舍：

- 用产品常识、旧 MSDS 或模板示例补值；
- 把无法判断的内容强行归入“最相近”的字段；
- 把图片/扫描页未读到当作源文件没有内容；
- 把多个不同研究、不同暴露途径或不同法规混成一句模糊话；
- 为了填满模板而写 `无数据` / `No data available`；
- 为了排版而删除数值范围、单位、限定词或否定结论。

事实不能进入模板时，使用 `source_only`、`omitted` 或
`not_applicable`，并写明原因。不能确认时使用 `unresolved` 或 `conflict`，
构建必须失败。

### 6. 换行整理：语义换行，不制造版式垃圾

值的换行要服务于阅读和字段结构：

- 普通说明文字按完整句子或语义分号换行；
- `字段：值` 必须保持在同一逻辑行；
- Section 11 的研究字段按结构化字段换行，不拆开 `Species:` 与物种；
- Section 14 的运输字段按 UN 编号、运输名称、危险类别、包装类别、特殊措施
  分行；
- Section 2 的 H/P 代码和完整语句各占逻辑行；
- Section 11 先按固定语义骨架对齐，再写值：11.1 的经口/吸入/经皮和
  11.7 的生育力/致畸形/体外遗传毒性分别占据其模板行。三列表格的中间
  子标签是锁定标签，不是值，不能因为源事实列表被压缩就把后续结果上移；
- 中文和英文翻译可以自然换行，但不能靠重复空格、Tab、空段落或单独的 `/`
  制造视觉对齐。

换行应写入已有值段落/值单元格中的 Word 换行，不得重建标签段落、表格或
模板行。

### 7. 双向闭环：源事实和输出值都必须可追溯

正向检查：每个 `fact_id` 都必须有一个处理结论：

```text
mapped / omitted / not_applicable / source_only /
duplicate / conflict / unresolved
```

正式构建中不能存在 `conflict`、`unresolved` 或无原因的遗漏。

反向检查：每个填入的模板值都必须在 `output_traceability` 中指出：

- 目标章节和目标槽位；
- 一个或多个来源 `fact_id`，或批准的派生记录；
- `written`/`merged` 决策；
- 适用的语义换行策略。

每个隐藏或不写入的值行也必须记录：

- 目标槽位；
- `hidden`/`not_written` 决策；
- `source_absent`、`explicit_missing`、`unsupported` 或
  `not_applicable` 状态；
- 具体原因。

### 8. 通过解释门后才能覆写

只有下列状态同时成立，才能克隆模板并进入值字段覆写：

- 源覆盖状态为 `ready`；
- 事实台账完整且每条事实有精确来源；
- S1-S16 映射已审核；
- 没有歧义、冲突、未读和未处理事实；
- 每个输出值都有追溯记录；
- 每个空值/隐藏决定都有目标和原因。

通过后，Agent 仍只能执行既有覆写白名单：写入/清空值单元格、请求必要的
完整样式行增删。标签、序号、加粗、字体、段落、单元格、表格结构、页眉页脚
和全局版式仍然不可修改。

值的粗体规则单独执行：模板中预先加粗的内容属于锁定标签/结构；所有
可写值必须继承值槽位的其他排版属性但保持非粗体。标签、子标签、表头和
复合路由前缀不得被值审计误分类。

## 最终交付前检查清单

- [ ] 原始源文件哈希已固定且没有混用其他源文件。
- [ ] 所有页、表格、图片、跨页续表和嵌入对象都有读取结果。
- [ ] `unmapped`、`unreadable`、`ambiguous`、`conflict` 均为空。
- [ ] 每条事实都有 `fact_id`、源位置和原文。
- [ ] 每条事实都有明确的映射/取舍结论。
- [ ] 每个写入值都有源事实或批准派生依据。
- [ ] 每个写入目标都记录了 CN/EN 输出值和语义换行策略。
- [ ] 每个隐藏/空值行都有状态和原因。
- [ ] 换行表达语义，没有空段落、Tab、重复空格或斜杠占位。
- [ ] 模板标签、序号、加粗和所有版式审计通过。
