# MSDS Agent 覆写 SOP v1.0

这套 SOP 解决两个相反风险：源文件不规则导致无法精准匹配，以及 Agent 为了填满模板而虚构、改写或错路由。Agent 不直接把源文件写进模板，而是先产出可审计的事实和路由，再由固定程序写入。

## A. 全局流程

1. 锁定一个原始 MSDS/SDS，记录路径、格式、模型、修订信息和 SHA-256；旧产物、模板示例和 PDF 不得作为事实源。
2. 全量清点正文、段落、表格、嵌套表格、页眉页脚、图片/扫描区域，建立 `source_coverage`；未读、冲突、不可解析区域阻断。
3. 建立原文事实台账：每条事实保存稳定 `fact_id`、原文、来源定位、源单元、数值/单位/范围/限定词和换行策略；此阶段不改写、不套模板。
4. 按含义匹配目标字段，不按源行号、模板剩余行或相邻标签猜测。允许源 Section 与目标 Section 不同，例如 S3 说明路由到 S2，但必须在 `source_mapping` 中记录源位置、目标槽位、理由和证据。
5. 只统一章节编号、标签边界、换行、列顺序、嵌套表格和字段顺序；已正确匹配的源句保持原文，不做同义改写、润色或常识补全。
6. 先生成 `output_traceability` 和 semantic write plan，列明每个值、目标 cell role、来源 fact、保留/合并/隐藏决定；未解决映射不得写模板。
7. 克隆最新模板，只调用唯一值写入入口写值单元格；标签、加粗、序号、表格几何和段落格式由模板拥有。
8. 写入后按局部规则隐藏完整空/不支持行，必要时才增删完整样式行，最后再做编号连续化；禁止用模板示例、CAS 常识或旧产物填空。
9. 依次通过事实来源、语义映射、全局源文保真、模板骨架/格式、局部 Section、空值/换行、双语一致性和渲染 QA；任一失败阻断发布。

## B. 全局硬限制

- `output_traceability.output_values` 不是证据；值必须绑定源事实或审核的翻译/派生。
- CN 值默认源文保真；EN 翻译必须绑定源事实并标记 `approved_translation` 和 `translation_reviewed=true`。
- 允许换位置、换字段、换行、去除重复字段标签；不允许换表述、改数字、改单位、改范围、删限定词、补条件、补物种、补实验结果。
- 每个源事实必须有 `mapped/omitted/not_applicable/source_only/duplicate` 之一的审核结论；`conflict/unresolved` 阻断。
- 每个写入值、隐藏行和结构增删都必须有追溯记录。

## C. 局部规则入口

局部规则只决定“识别到什么、去哪个目标、如何保留/隐藏”，不改变全局硬限制。

- S2：按 emergency/classes/label/signal/H-P/physical/health/environment/other 路由；S3 说明可跨 Section 路由到 S2，但不按位置复制。
- S8：PPE 与工程控制分离；呼吸、手部、手套材料、FKM/IIR/NBR、建议、眼睛、身体和控制参数分别匹配；源无通风不得生成通风建议。
- S9：按属性别名逐项映射，保留范围、单位和否定结论；NCO 含量独立成属性。
- S10：稳定性、分解产物、危害反应、避免条件、禁配物分别判断；源无字段不从常识补。
- S11：先按端点→研究→字段对齐，再写最终值列；11.1/11.2/11.7 中间子标签是标签。
- S12：生态端点与解释句分开；模板专有解释无源依据则隐藏。
- S13/S14：处置指令、运输温度、酸碱/食物禁配等保留源文，不做官僚化或生活化改写。

## D. Agent 交付记录

批准事实 JSON 必须提供 `overwrite_sop`：SOP 版本、全部阶段状态、已加载局部规则、跨 Section 路由清单、标准化允许范围和审计计划。缺少该记录时，程序在模板克隆前阻断。SOP 自证不能覆盖事实台账、源文保真或 DOCX 格式审计。
